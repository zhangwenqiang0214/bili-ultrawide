# 哔哩哔哩宽屏适配（带鱼屏）

一个油猴脚本，让 B 站在 21:9 / 32:9 带鱼屏和 4K 宽屏上不再浪费左右两侧的空间。

B 站的内容区宽度是**写死**的：首页和分区页封顶 1980px、热门页 1286px、动态页 1330px、播放页 2560px。
在 3440px 宽的屏幕上，两侧各有 500~900px 完全空着。这个脚本解除这些上限，并按窗口宽度自动计算每行放几张卡片。

以下数据实测于 **3440×1440**：

| 页面 | 原生 | 装了脚本 |
| --- | --- | --- |
| 首页 | 5 列 / 内容区 1980px | **8 列 / 铺满 3425px** |
| 分区页（`/c/tech` 这类） | 5 列 / 1980px | **8 列 / 铺满** |
| 热门页（含每周必看 / 入站必刷 / 排行榜） | 2 列 / 1286px | **5 列 / 铺满** |
| 动态页 | 1 列 / 1330px，左右侧栏各占一整列空高度 | **4 列瀑布流**，侧栏模块收成 183px 高的顶部信息条 |
| 播放页 | 播放器 1694×953，右侧是弹幕列表+推荐，滚动时视频跟着上下挪 | **播放器 2021×1137 并钉住不动**，右栏变成 1254px 宽的**评论区** |
| 顶栏（所有页面） | 2560px 居中 | **铺满** |
| 搜索页（综合 / 视频 / 用户 等各标签页） | 7 张/行，内容区卡在 2200px | **11 张/行 / 铺满**，卡片保持原生大小 |
| 首页顶部大 banner + 信息流那个 2×2 大推荐位 | 占掉 176px 高 + 4 个卡位 | **可一键去掉**（默认去掉） |
| 被拦截插件掏空的广告位 | 在信息流里留一个空洞 | **自动收掉**，后面的视频补位 |

四种页面均实测无横向滚动条。播放页上标题+播放器+工具栏底部落在 1435px，1440 高的屏幕一屏正好装下。

另外**顶栏**（logo / 分区入口 / 搜索框 / 右侧图标那一条）在所有带它的页面上都会拉满宽度，
包括播放页、动态页、搜索页 —— 它原本也是卡在 2560px 居中的。搜索页等未适配的页面**只拉顶栏**，
页面内容保持原样不动。

## 安装

1. 装 [Tampermonkey](https://www.tampermonkey.net/)（篡改猴）
2. 点这里安装脚本：[bilibili-ultrawide.user.js](https://raw.githubusercontent.com/zhangwenqiang0214/bili-ultrawide/main/bilibili-ultrawide.user.js)

需要支持 CSS `:has()` 的浏览器：Chrome/Edge 105+、Safari 15.4+、Firefox 121+。

## 可调参数

都在文件开头，一般只需要动第一个：

```js
const TARGET_CARD_WIDTH  = 380;   // 首页/分区页卡片目标宽度。380→8列 340→9列 300→10列 440→7列（3440 屏）
const POPULAR_CARD_WIDTH = 638;   // 热门页横条卡片目标宽度
const DYNAMIC_MAX_COLUMNS = 4;    // 动态页最多几列
const PLAYER_RATIO       = 0.62;  // 播放页播放器占内容区的比例，剩下的全给评论区
const HIDE_VIDEO_POD     = false; // 播放页是否连「合集/分P 列表」也隐藏（默认保留，否则多P视频没有选集入口）
const HIDE_HOME_BANNER   = true;  // 去掉首页顶部那张大 banner 图（占 176px 高）
const HIDE_HOME_SWIPE    = true;  // 去掉首页信息流左上角那个 2×2 大推荐位
const SIDE_PADDING       = 60;    // 页面左右留白，不要小于 60（原因见下）
```

## 设计说明

**按页面结构识别，不用网址白名单。** 所有规则都由 `html:has(#app > .bili-feed4)` 这类守卫限定，
页面上有什么就套哪套规则。好处是分区页、热门页各个子标签页自动覆盖，B 站以后新增同款页面也一样生效；
播放页以外的规则不会误伤播放页。`:has()` 是实时求值的，所以 `document-start` 注入样式也不怕元素还没渲染出来。

**动态页的瀑布流是自己算位置的，没用现成的两种 CSS 方案。** 两个现成方案各有硬伤：
`grid` 的行高由该行最高的卡片决定，矮卡片下面会留一大块空洞；`column-count` 没有空洞，
但无限加载时浏览器会把所有卡片重新分配到各列，正在看的内容会跳走。

这里的做法是：每张新卡片放进当前**最矮的那一列**，已经放好的卡片永不移动。所以既没有空洞，
加载更多也不会跳（实测 20→40 张，老卡片位移 0）。卡片高度变化（图片加载完、点了「展开」）
用 `ResizeObserver` 监听，只把**同一列**里它下面的卡片重新码一遍，其它列一个像素都不动。

两个实现细节值得记一下：`ResizeObserver` 必须指定 `{box: 'border-box'}`，默认的 `content-box`
收不到 padding 之类的非内容尺寸变化；回调要攒到 `requestAnimationFrame` 再统一重排，
否则图片批量加载时几十个回调逐个触发会抖。窗口窄到只能放一列时，脚本会把绝对定位全部清掉，
交还给 B 站原生的流式布局。

**播放页需要 DOM 搬运。** 评论区 `#commentapp` 在左栏内部，纯 CSS 挪不到右栏
（试过 grid + `display:contents`，UP 卡片会把共享的表格行撑高，把播放器往下顶 377px）。
搬运时机很关键：必须等 `<bili-comments>` 挂载之后再搬，否则会被 Vue 重新渲染回左栏
（实测 50ms 搬走、615ms 就被塞回去了）。

**播放器是钉住的，滚评论时视频一动不动。** B 站自带的 `.scroll-sticky` 是 `position: sticky`
但不给 `top`，靠 JS 随滚动渐进上移，视频会跟着上下挪。这里直接把 `top` 写死
（作者样式里的 `!important` 优先级高于它的行内 `style`）。

钉住的前提是**左栏总高必须塞进一屏**，否则底部内容永远滚不到。原生左栏 1701px、一屏只有 1376px，
超出 325px。所以左栏只留 标题 / 播放器 / 点赞工具栏，简介、标签、广告一并搬到右栏评论区上方；
播放器宽度也不再用硬编码的预留高度，而是**按左栏剩余空间反算**——遇到两行标题的视频会自动
把播放器缩一点，而不是撑破一屏。实测滚动到 800 / 1600 / 3000 / 6000px，播放器屏幕坐标恒为 172。

**空广告位是按「没有封面图」判的，不是按「没有视频卡」判的。** 装了 AdGuard / AdBlock 之后，
信息流里的广告位会被掏空，只剩一个占着格子的空壳。判断哪些是空壳时有个坑：**直播卡用的是
`.floor-card`，本身就没有 `.bili-video-card`**，按「没有视频卡」判会把直播卡一起误杀。
改成按「没有 `picture` 也没有 `img`」判，并且排除骨架屏和加载锚点（否则加载过程中布局会乱跳）。
实测首页 57 张、分区页 15 张真卡（普通卡 / 直播卡 / 骨架屏 / 加载锚点）零误杀，构造的空壳能被抓到。
规则是纯 CSS `:has()`，所以信息流后续加载出来的空壳也会实时收掉。

**顶部 banner 是压成 64px 占位，而不是 `display: none`。** 顶栏是 `position: absolute` 压在
banner 上的，直接删掉 banner 它会叠到分区导航上。另外未滚动状态的顶栏背景本来是透明的、
靠 banner 图垫底，所以要补一个实色背景（实测文字对比度暗色 12.48、浅色 17.58，都远高于 WCAG AA 的 4.5）。

**每个页面都是「保持它自己的原生卡片大小、只增加列数」，不是统一成一个尺寸。** 这点我一开始
在搜索页上搞错过：搜索页卡片原生只有 273px（B 站故意做小以便一行塞 7 张），我照首页的 380px 去套，
结果卡片变大、每行反而变少（2200px 下 7→5 张）。首页那个 380 恰好就是它的原生值，容易误以为是个通用基准。
另外搜索页的列数覆盖加了 `min-width: 2200px` 门槛 —— 原生响应式到 2200px 才排满 7 列，
比这更窄时交还给原生，避免任何宽度下出现密度倒退。

## 逆向出来的一些事实

记在这里方便以后 B 站改版时对照。这些都是从 B 站线上样式表里挖出来的，**随时可能变**：

- 首页 `.bili-feed4-layout` 的上限是 `calc(1980px + 2 * var(--layout-padding))`，外面 `#app` 还有一层 2560px。
- 分区页是和首页**完全不同**的另一套布局（`.feedchannel` + `.channel-page`），
  而且列数藏在一个构建哈希命名的 CSS 变量里（如 `--7c7fe7cc`），重新打包就会变名字，
  所以本脚本直接覆盖 `grid-template-columns`，不去碰那个变量。
- 热门页卡片宽度是 `calc(50% - 5px)`，靠 `:nth-child(odd)` 的 margin 撑两列间距，改列数后必须换成 flex `gap`。
- 播放器尺寸是 B 站按**视口高度**算的，把容器拉宽它不会跟着变大，只会在右边留黑边。
  必须显式给 `#bilibili-player` 宽度和 `calc(宽 * 0.5625 + 56px)` 的高度（56px 是控制条），
  这样弹幕层和控制条会一起等比缩放，零黑边。
- 两个会撑出横向滚动条的坑：首页吸顶占位块 `.fixed-channel-shim` 写死 `width: 100vw`（100vw 含滚动条宽度）；
  「换一换」按钮 `.feed-roll-btn` 是 `left: 100%` 再 `translate(10px)` 顶在容器外面的，
  右侧至少要留 50px。所以 `SIDE_PADDING` 不要小于 60。

## 不做什么

- 窗口窄于 1700px 时，动态页自动退回 B 站原来的三栏布局；窄于 2600px 时播放页完全不改。
  这个脚本是给宽屏用的，在普通屏幕上不添乱。
- 播放页的网页全屏 / 全屏模式下，脚本的播放器尺寸规则会自动让开
  （`:not(:has(.mode-webscreen)):not(:has(.player-full-class)):not(:has(:fullscreen))`）。
